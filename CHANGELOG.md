# Changelog

- **2026-09-12**
  - **Phase 0 — Setup**
    - Adds a reference layout for multi-device workspaces: `kernel/<version>/` for clean upstream source and a generic builder, `soc/<vendor-soc>/` for common patches, configuration and packages, `os/<distro>/` for device-neutral integration and tools, and `devices/<model>/` for device assembly, patches, calibration and state. Shared bases never import device policy; single-device ports need not reorganize.
    - Scopes `artifacts/`, `logs/` and device facts to the device project root, not the workspace root. Existing privacy, artifact classification and firmware-publication rules remain intact.
    - Records engineering stage, board identity and carrier/SKU alongside bootloader identifiers and build fingerprints. One presumed retail handset identified itself as an EVT board for a different product; `user/release-keys` did not establish production hardware.
    - Pins device operations to explicit transport identities, re-establishes the mapping after re-enumeration, and verifies product and slot immediately before writing. A second connected phone must never become an implicit target. The binding constrains the host too: a reachability probe never mutates host network configuration, a successful ping is not target identity, and one absent gadget MAC had a control script reconfigure an unrelated USB Ethernet dock's active IP settings.
    - Verifies required transport operations before building around them. One unlocked bootloader supported neither RAM boot nor partition fetch, leaving a built rescue image unusable through the intended channel.
    - Treats same-SoC firmware, DTs and signed recovery programmers as candidates, not proven recovery paths. Preserve prototype installations without verified replacements and obtain restorable backups before destructive experiments.
    - Distinguishes declared, enumerated, driver-bound and exercised capabilities. HAL names can reflect software ancestry, and installed firmware can cover unfitted components. One camera advertised 1080p at 30 fps through USB descriptors while Android exposed at most 1024×768 and 27 fps; neither established measured capture throughput.
    - Separates vendor A/B banks from verified Android seamless-update and fallback semantics. Empty security properties mean unknown, not unlocked; absent wear fields do not establish healthy storage, and coarse wear values do not exclude other faults.
  - **Phase 1 — Evidence**
    - Records acquisition method, origin, coverage and access failures alongside hashes. One reconstructed running DT preserved 2,740 property files, verified 2,222 emitted properties byte-identical and accounted for 518 redundant name properties; it remained distinct from an untouched boot-image DTB. All 2,839 manifest-listed files passed integrity checks, but the inventory was still not a restorable partition backup.
    - Carries hardware evidence levels into findings and separates running/deployed identities, service readiness and end-to-end behaviour. A registered sound card and successful silent playback do not establish acoustic qualification; deferred checks remain explicitly untested.
  - **Phase 2 — Research**
    - Adds AOSP / Android platform source without dropping existing source families: HAL interfaces, services, init/VINTF configuration, SELinux policy, boot-image tooling and shared native libraries. Platform contracts complement rather than replace exact OEM source, stock DTBs and vendor implementations.
    - Searches internal product codenames and OEM/ODM firmware archives alongside marketed names. Alternate-system images can reveal vendor implementation, but archive contents do not establish physical-device compatibility, flashing permission or recovery.
    - Cross-checks security advisories and fixes against the exact consumed source revision. One FastRPC investigation reproduced unchecked DSP-length parsing against a recent AOSP release despite an older bulletin describing that vulnerability class. Similarity and affected-chip lists alone do not establish exact CVE identity.
    - Traces untrusted firmware input across decoded lengths, signedness, arithmetic, cursor movement and copy bounds. One listener crash combined unchecked cursor advancement with a remaining-space calculation that wrapped positive; protocol desynchronization does not excuse unsafe parsing.
    - Turns shared defects into portable upstream reports with exact revisions, field evidence, reproduction prerequisites, minimal patches and before/after results. One real-parser gate covered five lengths — a captured field value, remaining space plus one, `0x7fffffff`, `0x80000000` and `0xffffffff` — recording SIGSEGV before the fix and containment afterwards. Sensitive evidence follows the project's disclosure policy; submission, acceptance, merge and release remain distinct.
    - Recommends optional `graft` navigation across indexed repositories, with exact-source verification and direct-search fallback. Missing index hits do not prove missing support. README adds it to “Pairs well with”; it is neither an independent source nor a required dependency.
  - **Phase 3 — Implementation and verification**
    - Separates restructuring from upgrades: hold upstream version, patches and configuration fixed and compare built payloads before changing versions. One split preserved `Image` and `System.map` bytes; downstream DTB and boot-image assembly still require verification.
    - Starts the pre-build patch battery from pristine upstream at the intended revision and checks/applies patches in order. One contaminated rebase check incorrectly classified a required header as absorbed upstream; the subsequent build failure forced its restoration.
    - Rechecks initialization after a real reboot, with matching kernel/modules and intended system identity. One upgrade exposed module coldplug ordering that prevented sound-card registration; later manual initialization was not boot-time verification.
    - Adds a post-upgrade storage sweep only after reboot and required runtime verification. Inventory retired kernels, modules, generations, roots and staging; preserve running and next-boot systems plus a complete known-good recovery path and dependencies. Archive required historical evidence on the host, use package-manager/GC removal rather than manual managed-file deletion, and record before/after space and retained recovery targets. Substantial GC recovery was operator-reported; no precise total or kernel-only attribution is claimed.
    - Builds the explicitly selected artifact and reports per artifact: one combined multi-target job concealed three completed targets behind a still-compiling desktop. Status queries never build; only completed store outputs survive cancellation.
    - Makes source preparation transactional: readiness derives from the actual patch assembly (one helper found no current declarations, applied zero of 47 patches, and stamped itself ready), each patch applies against its predecessors' result, success markers publish only after full success, and readiness fingerprints source identity plus ordered patch contents.
    - Treats deployment as a state machine — copy, next-boot selection, running-system switch and booted are separately observed postconditions; a closure already on the device is not an activation and explicit activation requests rerun. Required revalidation probes that time out, return empty output or lose transport are FAIL, never SKIP: one checker scored a timed-out partial output PASS and a dead transport SKIP, then exited 0.
  - **Commands and maintenance**
    - Aligns `/port-setup`, `/evidence-sweep` and `/flash-gate` with their phases. `/source-sweep` and `/port-research` continue delegating the authoritative source list; `/port-loop` keeps orchestration separate from phase content and never updates its rules mid-experiment.
    - Adds `/linux-phone-porting-update` to update the installed skill and companion commands, not the current device or development checkout. Resolves installation provenance, fetches the configured tracked branch, reviews the exact candidate and fast-forwards only clean, non-diverged installations. Preserves local edits and command collisions; no reset, forced replacement or implicit stash.
    - Documents safe command-link additions, existing-install bootstrap, scoped manager updates, manual-copy migration proposals, partial failures and revision reporting. Updates require a fresh session to load the new instructions; README removes destructive reset advice.

- **2026-09-06**
  - `/port-loop` no longer dies at three refutations. At invocation it asks the operator for a refutation budget — 5, 15, or unlimited — recorded in the ledger header; every third refutation on the same symptom forces a scope widening (the layer above, or the primary artefacts) rather than a stop, and the loop hands back only when a finite budget is spent, the device stops answering, or nothing testable remains. `/flash-gate`'s refutation question reads against that budget when running under the loop.
  - `/port-setup` ends by locking the project to the ruleset: it writes an explicit rule into the project's agent context files (`CLAUDE.md`, `AGENTS.md`, equivalents) that all work touching the device goes through the skill's phases and gates — no device action outside the ruleset.
  - Reboots are the agent's own when a channel exists: if the device is reachable over ssh, USB or fastboot, the agent reboots and continues; operator hands are reserved for what no channel reaches (battery pull, key combo, physically moving media).
  - Phase 0 sets the project layout: everything large, private or device-derived lives under a gitignored `artifacts/` tree classified by what it is (`private/`, `firmware-harvest/`, `android/`, `debug-evidence/`, `reference/`), publishable firmware goes to a sibling repository with its own history derived only after redaction, `logs/` takes one subdirectory per boot, and a README maps every path to its class with hashes.
  - Phase 0 proves the control channels before any flash: `adb` and `fastboot` exercised against the device (an untested install is not a channel), plus at least one post-boot channel into the target Linux — USB-gadget Ethernet, serial ACM, ssh over network or USB — recorded with addresses.
  - A still-bootable Android stays available as an evidence channel for the whole port, not just setup: boot it deliberately when a question is best answered there (a working vendor driver's probe read live next to the mainline failure), but never conclude anything about mainline behaviour from Android behaviour without a cross-check.
  - The `/port-loop` refutation budget is a per-invocation, per-session choice: asked every time the loop starts, never carried over from a previous session nor recorded as a project setting.
  - Research per iteration is fresh, not recycled: the refutation narrowing the question does not waive the sweep — `/port-loop` re-runs it against the narrowed framing and each pass must return at least one finding the ledger does not already contain, and `/flash-gate` question 2 now asks when the source was found, refusing a backing that only comes from earlier iterations when the framing has changed.
  - The operator-hands rule now covers disappearance signals: a power-off, a dropped channel or a gone-silent device is ambiguous between "not done yet" and "done" — the agent must watch the drop as an event or pair the operator's done-confirmation with a failing probe, never read silence alone, and must poll on a short interval and re-ask within a bounded wait instead of freezing on a request the operator may not have registered.
  - Phase 2 gains a sister-device sweep: it enumerates ports of same-family models (sibling variants under the same marketing name, near-neighbours on the same board generation), diffs each port's board files (dts, defconfig, firmware blob lists) component-by-component against the phase 0 inventory, and adopts only what the diff confirms against this variant's spec sheet and stock DTB — a sister device is a lead, not a precedent. Phase 0 now records sibling models' codenames alongside the device identity to feed that sweep.
  - `/source-sweep` and `/port-research` no longer restate the source list; they delegate to the skill's phase 2, so the list has one authoritative home.
  - The skill's frontmatter description now states only when to use the skill (hardware bring-up / debug on a phone, unlocked bootloader required) — no workflow summary.
  - Phase 0's component-vs-spec-sheet comparison invokes `find-docs` by name (fallback: plain web search) instead of generic "web-research or documentation-retrieval skill" phrasing.
  - Phase 0: A/B slot state is decoded from the on-disk structure (one SoC keeps it in GPT partition-entry attribute bits, not the documented bootloader-control partition), and the tries-remaining budget is refilled after any crash-loop before interpreting the next boot failure.
  - Phase 0: a media-failure verdict that would retire the device must survive a re-probe in a later session — one flash region refused writes twice (cold power-off included) and wrote clean 3/3 the next day against a full zero-error read scan.
  - Phase 1: the kernel ACM console bullet now requires verifying the console survives the reporting context (payloads emitted inside `panic()` cannot reach workqueue-deferred console writes) and testing the premise with a kernel crash injector before spending the flash; ramoops rot now includes warm reboots; a new rule treats an unchanging polled status register as a latch until proven live by stimulus; and total channel loss after suspend/resume is read as three-valued — dead, hung, or alive with a dead channel driver — with the device's own journal as the arbiter.
  - Phase 2: silence from a DSP can be an unanswered AP-side callback rather than dead silicon; a missing fused capability is not a missing sensor (strings-scan the harvest for the refused identifier); existing patches are re-verified against every downstream DT held (newest stock OTA, original backup, custom ROM), and vendor flash scripts are read before trusting — one ships slot-blind.
- **2026-09-05**
  - Phase 0 now inventories every component against the official spec sheets.
  - Phase 0 records the storage's own wear/lifetime percentage before anything is diagnosed as failing (measured: that reading overturned a false "storage is dying" verdict; the real fault cleared on one more stock-ROM fastboot flash).
  - Phase 0 harvests deeper from rooted stock — treated like bootloader unlocking: the user roots the device, the skill never provides the steps.
  - Phase 0 records the newest community custom ROM as an optional up-to-date source (measured: an unofficial recent-Android build was the most responsive OS seen on one device).
  - Setup asks for the target userspace shell instead of assuming one, and strongly recommends the distro's own shell where it ships one.
  - Phase 2 gains a source family: the SoC vendor's mainline collaboration project (e.g. github.com/qualcomm-linux).
  - Phase 2 invokes its companion skills by name (`linux-kernel-development`/`linux-kernel-crash-debug`, `find-docs`, `wigolo`), each with a plain-tools fallback so the skill still works when none is installed.
  - Phase 3 gains a strict pre-rebuild gate: patches apply cleanly, every referenced symbol exists in the tree, every config option exists in the kernel's Kconfig (non-existent options are silently ignored), and touched units compile alone — before any full kernel rebuild (measured: four consecutive rebuilds burned on missing symbols in unchecked patches).
  - Phase 3 gains an edit-precision rule: changes land by reading the exact current lines and writing the exact replacement; an edit needing "repair" is redone from a fresh read, and self-inflicted breakage then hand-fixed is a defect, not a workflow.
  - Phase 3 gains an operator-hands rule: when a step needs a physical action, name the exact action and its direction and verify it happened from an observable signal before continuing — never proceed on having asked.
