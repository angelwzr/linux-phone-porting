- **2026-09-20**
  - **Evidence rules from a later port stage.** Five new measured rules, none device-named:
    - One-direction-dead USB networking: ping from the host while reading the device's interface TX/RX counters over a surviving channel — counters rising only inbound split link-down from device-cannot-transmit. A read-only rootfs remount after a failed resume kills sshd and networking with identical outward silence, so check the mount before blaming the gadget.
    - A host-side USB id plus dead ssh proved neither "Android fallback" nor a failed boot while the target OS was up and responsive: host-visible signals establish channel state only; obtain OS identity through a working channel and record a channel failure until then.
    - A hard reset during suspend entry masquerades as a resumed-but-dead device (no panic, no pstore). `boot_id` + journal continuity discriminates; the `pm_test` stage ladder (freezer → devices → platform → processors → core) localizes entry faults to the SoC power-collapse transition — missing wake-controller node, absent parent collapse domain, firmware-inconsistent idle StateIDs — rather than to any device driver.
    - Detached recovery units (`systemd-run`) run with a minimal PATH: sleeps silently no-op, scripts race their own readiness checks, and a reboot safety net can fire on a false negative — destroying the state it existed to diagnose. Absolute paths, per-step timestamped logging, destructive fallbacks gated on in-script verified preconditions.
    - Module load order is an experiment variable: camera/lens modules in `modules-load` ahead of audio DSP bring-up broke speaker-path registration on every boot, while runtime loading after audio init kept both paths working — order-dependence, not module presence.
